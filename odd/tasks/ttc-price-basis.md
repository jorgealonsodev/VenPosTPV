# TTC price basis
Objective: make the price the TPV charges, books in `order_meta` and records in the cash drawer the same tax-included, reduction-applied price PrestaShop books, instead of the Web Service base price (tax-excluded, no reductions) it stores today. Branch: `fix/ttc-price-basis` (on top of `fix/checkout-price-integrity`).
Delivery: feature-branch-chain inherited; runtime `.runtime/php-8.5.12/bin/php`. No PrestaShop module deployment in this feature (explicitly deferred by the user).
Slice boundary: this branch is stacked on `fix/checkout-price-integrity` (`2080672`), so this feature's own work units are measured from `2080672`; the total the harness reports for the branch includes the inherited stack.

## Specs
S1. "haz lo que consideres mas optimo" — parent-identified defect, verified against the live shop: `CatalogSyncService` stores Web Service `products.price` into `catalog_product.price` (product 1 = 23.90, tax-excluded base, no reductions), while the shop's real price is 23.14 TTC (19.12 net x 1.21 "IVA ES 21%") and `modules/tpvconnect/controllers/front/orders.php` books `Cart::getOrderTotal(true, Cart::BOTH)` ignoring the submitted `price`. Every sale diverges (0.76 per unit on product 1). `public/assets/js/stores/useCart.js:63` and `src/Service/Cart/CartService.php:59` already compute `iva = total * 0.21 / 1.21`, so TTC is the semantics the system already expects.
S2. "¿Qué hacemos con la Capa 2 (la integridad real del dinero en PrestaShop)? que crees qeu debemos hacer" — the user asked for a recommendation on the money-integrity layer.
S3. Authorized scope, verbatim selection: "Solo el paso 1 — base TTC en el sync (recomendada)" / "Corrige la divergencia sistemática sin desplegar nada en PrestaShop. Al terminar decides si seguimos con la cotización."
S4. Deferred follow-up, verbatim (chosen earlier for Capa 2, not authorized for implementation now): "C — Pre-cotización antes de cobrar (recomendada)" / "Nuevo endpoint en el módulo PS que calcula el total real SIN crear el pedido. El TPV lo muestra y lo usa antes de abrir el modal de pago. La divergencia en el mostrador se vuelve imposible."
S5. "si necesitas consulta context7" — price semantics must follow documented PrestaShop behaviour, not assumption: `/api/products/{id}?price[key][use_tax]=1&price[key][use_reduction]=1` returns the calculated specific price (verified 23.140000 TTC, 19.120000 net, 28.920000 without reduction); the same parameter on the collection endpoint returns null; the configured API key cannot read `configurations`, `taxes`, `tax_rules` or `specific_prices` (401).
