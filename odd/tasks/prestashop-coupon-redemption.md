## Implementation boundaries
Use native CartRule eligibility, application, totals and consumption, not a local balance or a PUT that decrements usage separately. A preview must not create an order or consume usage. Preserve normal checkout behavior. Detect changed/expired preview, validate coupon and totals again at order creation, and suppress ambiguous automatic retries. Any claim of cross-channel atomicity needs independent evidence; the native implementation is not assumed atomic merely because it decrements quantity. Never present this as a persistent-balance gift card.
Work is sliced into module contract and TPV integration; tests/docs travel with behavior. Forecast: substantial multi-area feature, two sequential work units, no deployment. If safe minimum exceeds these bounds or needs core/web overrides, stop with the exact limitation instead of broadening silently.

## Module correction acceptance (T2, S1-S5)
C1. Native PS8.1.7 `CartRule::checkValidity(Context, alreadyInCart=false, display_error=true, ...)` returns null for valid rules with display_error=true, true only with display_error=false. Active/quantity/date checks only run when alreadyInCart=false. Preview must use correct native semantics; redemption of an attached rule must freshly check active/quantity/date and native restrictions without treating duplicate-in-cart as invalid. Tests must model these flags faithfully.
C2. Native Cart::getProducts uses cart_quantity for the requested cart amount; quantity can mean available stock. Normalize request and native products separately and test with stock quantity deliberately different from cart quantity.
C3. Db::executeS defaults use_cache=true. GET_LOCK and RELEASE_LOCK must explicitly bypass cache. Two preview carts for the same coupon must serialize module redemption by coupon identity as well as cart identity; deterministic acquisition and finally release even on partial failure. Do not claim coordination with web checkout or native runtime concurrency proof from doubles.
C4. Revalidate attachment of the quoted rule and its effective discount and before/after totals, not only payable amount. Regression: quote100 minus10 equals90; remove rule and lower product to90; redemption must reject before callback and usage changes. Replay must correspond to the same quoted coupon/cart order, not a coincidentally matching amount.
C5. Explicit coupon:null or other malformed bindings must reject422 rather than escaping the coupon path via isset; absent coupon alone retains ordinary checkout. Test no order/usage side effects on rejection.
Capture actual behavioral RED for these defects with faithful native doubles before fixes, then focused and full module GREEN using --do-not-cache-result. The initial delivery's syntax error was not a functional RED. One correction batch, then a targeted verifier recheck of these blockers only.
